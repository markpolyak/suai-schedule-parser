# suai-schedule-parser

Парсер расписания ГУАП (<https://guap.ru/rasp>) и движок проверки гипотез о
переносе занятий: не наложится ли пара на другую, найдётся ли свободная
аудитория, не придётся ли группе ехать в другой корпус.

Описание самого интерфейса guap.ru/rasp — в **[API.md](API.md)**.

## Установка

Нужны `requests`, `beautifulsoup4`, `lxml` (в Anaconda уже есть).

## Быстрый старт

```bash
python -m suai_rasp dump          # слепок расписания → schedule.json (53 запроса, ~30 c)
python -m suai_rasp validate      # sanity-check: двойных бронирований, двойных переездов через
                                   # весь город и окон у групп в опубликованном расписании — 0
                                   # (единственное расхождение — 1 группа с окном, см. README).
```

Дальше — работа со слепком, сети не требует:

```bash
# расписание группы
python -m suai_rasp show --group 1232

# свободные аудитории в слоте, где поместится поток из 2 групп
python -m suai_rasp free --day Среда --slot 3 --campus "Б. Морская 67" --groups 2

# куда можно перенести конкретное занятие
python -m suai_rasp slots --group 1232 --subject "Обработка навигационной" --kind Лекция

# проверить конкретный перенос
python -m suai_rasp move --group 1232 --subject "Обработка навигационной" --to "Четверг 3"
```

Пример вывода `move`:

```
ГИПОТЕЗА:
  • Понедельник 5 пара (17:00—18:30) [каждую] | Лекция | Обработка навигационной
    информации | ауд. 13-04 (Б. Морская 67) | Езерский В.В. | гр. 1232
      →  Четверг 3 пара (13:00—14:30) [каждую] | ...
ВЕРДИКТ: ВОЗМОЖНО
```

и при конфликте:

```
ВЕРДИКТ: НЕВОЗМОЖНО
Конфликты:
  ✗ [teacher] Ананенко В.М. — Среда, 1 пара: одновременно «Системы управления
    летательными аппаратами» (Лекция) и «...» (Практическое занятие)
  ✗ [group] 1232 — Среда, 1 пара: ...
```

## Что проверяется

* двойное бронирование группы, преподавателя, аудитории — с учётом чётности недели;
* переезд между корпусами в соседних парах (Б. Морская ↔ прочие — жёсткий запрет,
  Ленсовета ↔ Гастелло — предупреждение);
* **два и более переезда через весь город за один день** (`kind="commute"`) —
  не только соседние пары, а вообще все посещённые за день корпуса подряд:
  уехал на Б. Морскую (или с неё) и вернулся — запрет, даже если между
  переездами есть окно. Переезды **между Ленсовета и Гастелло в счёт не идут
  вообще** — они рядом, это не «через весь город», и такое не запрещено,
  сколько бы раз за день ни повторилось;
* **окно ≥ 2 пар между занятиями за день, не объяснённое переездом**
  (`kind="window"`) — только у **студенческих групп**, к преподавателям
  отношения не имеет (для них это обычная практика — читать один и тот же
  курс разным потокам в разное время дня);
* вместимость аудитории — по оценке «сколько групп туда исторически ставили»;
* какие существующие проблемы гипотеза, наоборот, чинит.

Два новых пункта — **не эмпирический инвариант** опубликованного расписания
(в отличие от первых двух): ГУАП такие вещи при составлении не разбирает.
С учётом сужения правил (только Б. Морская в счёт переездов, только группы
для окон) в реальном слепке из этого осталась всего 1 группа с окном и ни
одного случая двойного переезда через город — то есть школа фактически и так
не допускает возврата на Б. Морскую в течение дня, просто явно это не
проверяет. Это дополнительные запреты именно для проверки **новых** гипотез о
переносе — старые нарушения не мешают, если гипотеза их не касается.
Отключаются параметрами `check_campus=False` / `check_windows=False` у
`validate()` и `check_hypothesis()`; пороги — константы
`MAX_DAILY_CAMPUS_HOPS` и `MIN_IDLE_WINDOW` в `conflicts.py`.

Аудитории-заглушки (`(вне сетки)`, `(Дистант)`, корпус без номера комнаты) и
занятия вне сетки из проверки занятости исключены — см. §6.5—6.6 в API.md.

## Python API

```python
from suai_rasp.model import Schedule, Ref
from suai_rasp import conflicts as C

sch = Schedule.from_json("schedule.json")

gid = sch.find_group("1232")
lesson = [l for l in sch.by_group[gid] if "Инерциальные" in l.subject][0]

print(C.report(sch, [C.Move(lesson, day="Четверг", slot=3)]))   # вердикт по гипотезе
C.candidate_slots(sch, lesson)                                   # все допустимые слоты
C.free_rooms(sch, "Среда", 3, campus="Б. Морская 67", min_groups=2)
C.check_hypothesis(sch, C.swap(a, b))                            # (новые проблемы, исчезнувшие)
C.validate(sch)                                                  # всё расписание целиком
print(C.day_grid(sch, "group", gid))                             # сетка занятости
```

`C.Move(lesson, day=..., slot=..., week=..., room=...)` — любое подмножество полей.
Список `Move` проверяется совместно, поэтому пакетные перестановки
(«освободить пятницу целиком») формулируются одной гипотезой.

### Совместная расстановка нескольких занятий (plan.py)

```python
from suai_rasp import plan as P

units = [P.Unit("Лекция", [lecture], rooms=[32, 145, 201], days=["Понедельник", "Вторник"]),
         P.Unit("ЛР", [lab], rooms=[88, 90])]
results = P.search(sch, units, accept=P.same_day, max_results=100)
```

**Всегда указывайте `Unit.rooms` явным списком** (id аудиторий, куда это занятие
реально можно ставить — например, через `C.free_rooms(...)` или
`C.room_load_profile(sch)`, отфильтрованные по корпусу/типу занятия), а не
оставляйте его пустым. Пустой список означает «любая аудитория из справочника»
(~250 штук), и тогда на **каждой** проверяемой комбинации слотов
`search()` будет проверять занятость всех ~250 аудиторий для каждой единицы —
при 3–4 единицах это легко превращает перебор в минуты, а то и не даёт ему
завершиться за разумное время. С явно ограниченным списком (те же 5–10
аудиторий, куда предмет реально ставят) поиск занимает доли секунды.
Общая сложность `search()` экспоненциальна по числу единиц (`O(L^U)`, где
`L` — число допустимых слотов на единицу, `U` — их количество), поэтому
сокращать пространство перебора по аудиториям — единственный дешёвый способ
не дать ему разрастись зря.

Структура кода и формат данных описаны в [API.md §9](API.md#9-инструмент-в-этом-репозитории).
