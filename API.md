# API расписания ГУАП (guap.ru/rasp)

Реверс-инжиниринг публичного расписания ГУАП: что за интерфейс, как из него забрать
полный слепок семестра и какие доменные правила из него следуют.

Данные проверены на слепке **осеннего семестра 2026/27** (сборка сайта `2026-08-24`,
8797 занятий, 585 групп, 773 преподавателя, 249 аудиторий, 53 кафедры).

---

## 1. Коротко о главном

| | |
|---|---|
| Тип интерфейса | **Нет JSON/REST API.** Только серверный рендеринг HTML с фильтрами в query-string |
| Стек | IIS 10 / ASP.NET, `Content-Type: text/html; charset=utf-8` |
| Кэширование | `Cache-Control: no-store, no-cache` — ETag/Last-Modified нет, условные запросы бесполезны |
| Методы | Только `GET`. `HEAD` → `405 Method Not Allowed` |
| Авторизация | Не нужна, cookie не требуются |
| Полный слепок | **53 запроса** — по одному на кафедру (см. §5) |
| Единица данных | Одно занятие = слот (день + пара + чётность) + аудитория + кафедра + список преподавателей + список групп |

## 2. Эндпоинты

### 2.1 `GET https://guap.ru/rasp/` — расширенный вид

Основной источник. Отдаёт **все** поля занятия.

### 2.2 `GET https://guap.ru/rasp_sm/` — компактный вид

Та же выборка, компактная вёрстка. **Не содержит кафедру** и тип занятия даёт
аббревиатурой (`Л`, `Пр`, `Лаб`) в атрибуте `title`. Для парсинга бесполезен —
используйте `/rasp/`.

### 2.3 Параметры фильтрации

Все — необязательные, числовой id из справочника (§3).

| Параметр | Смысл | Пример |
|---|---|---|
| `gr` | группа | `?gr=6266` → гр. 1232 |
| `pr` | преподаватель | `?pr=2707` |
| `ch` | кафедра | `?ch=13` |
| `ad` | аудитория | `?ad=34` |

Поведение:

* **Комбинируются по И.** `?gr=6266&pr=2707` → только пары этой группы у этого
  преподавателя. Порядок параметров не важен.
* **Без параметров** — форма поиска без расписания.
* **Повтор одного параметра** (`?gr=6266&gr=6703`) — не multi-select, выдаёт
  «Совпадений не обнаружено».
* **Несуществующий id** — `HTTP 200` и «Совпадений не обнаружено», не 404.
* **Выбора семестра/недели нет.** Сайт всегда отдаёт текущий семестр. Прошлые
  семестры недоступны — если нужна история, храните свои слепки.

Форма на странице собирает URL этим кодом (`<script>` внизу `/rasp`):

```js
if (selGroup.value) params1 += `gr=${selGroup.value}&`;
if (selPrep.value)  params1 += `pr=${selPrep.value}&`;
if (selChair.value) params1 += `ch=${selChair.value}&`;
if (selRoom.value)  params1 += `ad=${selRoom.value}&`;
```

## 3. Справочники

Лежат в `<select>` на любой странице `/rasp` — отдельного эндпоинта нет.

| `id` элемента | Сущность | Параметр | Кол-во | Формат подписи |
|---|---|---|---|---|
| `selGroup` | группы | `gr` | 585 | `1232`, `м611`, `8652кс`, `пд14м51` |
| `selPrep` | преподаватели | `pr` | 773 | `Иванов И.И., доцент, канд. техн. наук, доцент` |
| `selChair` | кафедры | `ch` | 53 | `13`, `ПД`, `ПН`, `ИТ` |
| `selRoom` | аудитории | `ad` | 249 | `13-03а&nbsp;(Б. Морская 67)` |

```html
<select class="form-select guap-tom-select" id="selGroup" name="selGroup">
    <option value="">–нет–</option>
    <option value="6266">1232</option>
    ...
```

Замечания:

* Имена групп уникальны. У аудиторий уникальна только **полная подпись вместе с
  корпусом**: 47 номеров встречаются в двух корпусах сразу — `23-09` есть и на
  Б. Морской, и на Ленсовета, `32-03` — на Б. Морской и на Гастелло. Искать
  аудиторию по одному номеру нельзя, всегда сверяйте корпус.
* Id сквозные и стабильны в пределах семестра; при пересборке расписания на новый
  семестр не гарантируются — привязывайтесь к именам, id считайте кэшируемыми.
* Id разрежены и не последовательны (встречаются `98765`, `777351`) — перебор
  диапазона не работает, только справочник.
* В подписи аудитории корпус указан в скобках в конце; `&nbsp;` перед скобкой.

## 4. Структура ответа `/rasp/`

Расписание лежит в `div.content`. Плоская последовательность: заголовок дня →
заголовок пары → карточки занятий.

```html
<h4 class="text-danger ...">Понедельник</h4>                 <!-- день -->
    <div class="mt-3 text-danger">2 пара
        <small class="opacity-50">(11:10—12:40)</small></div> <!-- номер пары + время -->
    <div class="mb-3 py-2 d-flex gap-2">                      <!-- карточка занятия -->
        <div class="week2" title="нижняя (четная) неделя">▼</div>  <!-- маркер чётности -->
        <div>
            <div class="fs-6 lh-sm opacity-50">Практическое занятие </div>  <!-- тип -->
            <div class="lead lh-sm">Системы управления летательными аппаратами</div>
            <div class="opacity-75">
                ауд. <a href="?ad=34">13-03а&nbsp;(Б. Морская 67)</a>
                —&nbsp;<a href="?ch=13">Кафедра 13</a><br />
                преп:&nbsp;<a href="?pr=2707">Ананенко В.М., доцент, ...</a>.&nbsp;&nbsp;
                гр:&nbsp;<a href="?gr=6703">1331</a>, <a href="?gr=6266">1232</a>
            </div>
        </div>
    </div>
```

Правила разбора:

| Что | Как достать |
|---|---|
| День | `h4` с текстом из списка дней; `Вне сетки расписания` — особый блок |
| Пара | `div.mt-3.text-danger`, текст `^(\d+) пара` |
| Карточка | `div.mb-3.py-2.d-flex` |
| Чётность | первый дочерний `div` карточки: класс `week1` = верхняя (▲, нечётная), `week2` = нижняя (▼, чётная), пустой класс = каждую неделю |
| Тип занятия | `div.fs-6` (внимание: у «Практическое занятие » висит хвостовой пробел) |
| Дисциплина | `div.lead` |
| Аудитория / кафедра / преподаватели / группы | ссылки внутри карточки, id — из `href="?ad=«…»"` и т. д. |

Все id восстанавливаются из href одним выражением: `\?(gr|pr|ch|ad)=(\d+)`.
Текст содержит `&nbsp;` (U+00A0) — нормализуйте пробелы.

### 4.1 Шапка страницы (метаданные)

```html
<p class="lead text-success lh-sm">Осенний семестр 2026/27 учебного года<br />
    <small>(сборка: 2026-08-24)</small></p>
<div class="alert alert-light">Сегодня <nobr>вторник, 25 августа 2026 г.</nobr><br />
    <span class="week2">▼ 52 нижняя (четная) неделя</span></div>
```

Отсюда берутся семестр, **дата сборки расписания** (по ней видно, что расписание
поменялось) и текущий номер/чётность недели — нужны, чтобы соотнести ▲/▼ с
календарными датами.

### 4.2 Строка активного фильтра

```html
<div id="result" class="opacity-50">Фильтр: гр. 1232, Ананенко В.М., ...</div>
```

Удобная проверка, что сервер понял запрос. При пустой выдаче вместо неё —
`Совпадений не обнаружено.`

## 5. Как получить полный слепок расписания

**Проход по кафедрам — 53 запроса, и это весь университет.**

Проверено: объединение выдач по всем 53 кафедрам даёт 585 групп, 773
преподавателя и 249 аудиторий — ровно столько же, сколько в справочниках, а
дублей нет ни одного. То есть каждое занятие принадлежит **ровно одной** кафедре,
и выборки по кафедрам образуют точное разбиение. Выборка по конкретной группе
совпадает с тем, что даёт кафедральный дамп, запись в запись.

Сравнение стратегий:

| Стратегия | Запросов | Дубли |
|---|---|---|
| **по кафедрам (`ch`)** | **53** | нет |
| по группам (`gr`) | 585 | много (потоковые лекции) |
| по аудиториям (`ad`) | 249 | много |
| по преподавателям (`pr`) | 773 | много + теряются занятия без преподавателя |

Вежливость: ~0.4 с между запросами, полный дамп — около 30 секунд. Rate limit не
обнаружен, но сервер университетский, кэшируйте локально.

## 6. Доменная модель, извлечённая из данных

### 6.1 Временна́я сетка

| Пара | Время | Занятий в семестре |
|---|---|---|
| 1 | 09:30—11:00 | 807 |
| 2 | 11:10—12:40 | 1354 |
| 3 | 13:00—14:30 | 1451 |
| 4 | 15:10—16:40 | 1354 |
| 5 | 17:00—18:30 | 1050 |
| 6 | 18:40—20:10 | 791 |
| 7 | 20:20—21:50 | 288 |

Дни: понедельник — суббота (воскресенья в расписании нет). Перерыв между парами
10 минут, между 3 и 4 парой — 40 минут (обед), между 4 и 5 — 20 минут.

### 6.2 Чётность недели

Три значения: **каждую** (3587 занятий), **верхняя/нечётная ▲** (2706),
**нижняя/чётная ▼** (2504). Два занятия конфликтуют, если хотя бы одно из них
идёт каждую неделю либо их чётности совпадают.

### 6.3 Типы занятий

`Практическое занятие ` (3999), `Лекция` (2351), `Лабораторное занятие` (2092),
`Курсовая работа` (297), `Курсовой проект` (58).

### 6.4 Корпуса

| Корпус | Аудиторий |
|---|---|
| Б. Морская 67 | 117 |
| Гастелло 15 | 73 |
| Ленсовета 14 | 50 |
| Московский 149 | 6 |
| ИПМаш РАН, Дистант, «вне сетки» | по 1 (псевдо-аудитории) |

### 6.5 Псевдо-аудитории — не проверять на занятость

Пять записей не обозначают физического помещения:

* `(вне сетки)` — id 5;
* `(Б. Морская 67)`, `(Гастелло 15)` — пустой номер, «где-то в корпусе»
  (военный учебный центр, физкультура);
* `(ИПМаш РАН)`, `(Дистант)`.

На них приходится 1770 занятий. Считать их «занятыми» нельзя — иначе получите
15 ложных конфликтов только по id 26.

### 6.6 Занятия вне сетки

1702 записи (19 %) в блоке «Вне сетки расписания»: есть дисциплина, тип, кафедра
и группы, но **нет дня, пары и преподавателя**, аудитория всегда `(вне сетки)`.
Это дисциплины по выбору и подобное. При проверке конфликтов их надо
игнорировать; при переносе — они кандидаты на «поставить в сетку».

### 6.7 Потоки и коллективные занятия

Одна запись может содержать до **23 групп** (потоковая лекция) и до **19
преподавателей** (физкультура, военный учебный центр). 1176 записей — потоковые.
При проверке конфликтов занятие блокирует все свои группы и всех преподавателей
одновременно.

## 7. Эмпирические инварианты (база для проверки гипотез)

Полная валидация опубликованного расписания даёт **0 жёстких конфликтов** —
значит эти правила составители соблюдают, и на них можно опираться:

1. **Группа** не имеет двух занятий в одном слоте. Нарушений: 0.
2. **Преподаватель** не имеет двух занятий в одном слоте. Нарушений: 0.
3. **Аудитория** не занята дважды в одном слоте. Нарушений: 0 (единственное
   исключение — `спортзал (Ленсовета 14)`, где две группы физкультуры идут
   параллельно; это норма, а не ошибка).
4. **Переезд между корпусами в соседних парах** — только `Ленсовета 14 ↔
   Гастелло 15` (531 случай; здания рядом). Между `Б. Морская 67` и любым другим
   корпусом в соседних парах — **ни одного случая**. Значит это жёсткое
   ограничение: перенос, требующий такого переезда, надо считать невозможным.
5. **Вместимости аудиторий сайт не публикует.** Верхняя оценка — максимальное
   число групп, которое исторически ставили в эту аудиторию
   (`max_groups_seen`), плюс типы занятий, которые в ней проводились (лаборатория
   с оборудованием не годится под лекцию потока).

Пункт 6 — формально **не эмпирический инвариант** (правило не проверялось на
исходных данных при проектировании, в отличие от пп. 1—4), но по факту
опубликованное расписание ему подчиняется почти без исключений:

6. **Не более 1 переезда через весь город за день, не более одного окна ≥ 2
   пар за день у группы.**
   * «Переезд через весь город» — это только `Б. Морская 67 ↔` любой другой
     корпус. Переезды между `Ленсовета 14` и `Гастелло 15` (сколько угодно раз
     за день) в счёт не идут — они рядом, это пп. 4 выше, а не это правило.
   * Окно проверяется **только у студенческих групп**, не у преподавателей —
     те штатно читают один курс разным потокам в разное время дня, это не
     проблема расписания.
   * С такой формулировкой в опубликованном расписании — **0 дней с 2+
     переездами через город** и **1 группа с окном ≥ 2 пар** (`м456`, среда,
     между «Производственная санитария» и «Техногенные системы и
     экологический риск»), см. `python -m suai_rasp validate`.
   * Проверка (`kind="commute"` / `kind="window"` в `conflicts.py`) всё равно
     включена по умолчанию — но срабатывает как «невозможно» только для
     **новых** нарушений, которые вносит сама гипотеза; существующие в
     расписании до переноса не мешают. Отключается через
     `check_campus=False` (переезды) / `check_windows=False` (окна).

## 8. Подводные камни

| Проблема | Что делать |
|---|---|
| `HEAD` возвращает 405 | проверять доступность только через `GET` |
| Неверный id → 200 | искать маркер `Совпадений не обнаружено` |
| `&nbsp;` (U+00A0) везде в тексте | нормализовать пробелы перед сравнением |
| `Практическое занятие ` с хвостовым пробелом | `strip()` при сравнении типов |
| Тип занятия у карточки — по классу `div.fs-6`, а не по позиции | не полагаться на порядок дочерних узлов |
| Расписание пересобирается | сверять `(сборка: YYYY-MM-DD)` из шапки перед анализом |
| Прошлые семестры недоступны | хранить собственные слепки |
| Один и тот же предмет может идти в разные недели в разных аудиториях | это две отдельные записи, а не дубль |
| Номер аудитории без корпуса неоднозначен (47 случаев) | искать по полной подписи `«23-09 (Б. Морская 67)»` |
| Одну дисциплину могут читать разные преподаватели разным потокам | фильтровать выборку ещё и по преподавателю |
| Разметка вида — Bootstrap-классы | при редизайне сайта парсер сломается; тест — `validate` должен давать 0 по пп. 1—6 §7 (двойные бронирования, дальние переезды, 2+ переезда через город, окна у групп) |

## 9. Инструмент в этом репозитории

```
suai_rasp/
  fetch.py      HTTP-клиент с файловым кэшем и троттлингом
  parse.py      HTML → объекты Lesson, справочники, метаданные
  model.py      модель, индексы (по группам/преподавателям/аудиториям), JSON
  conflicts.py  проверка гипотез, свободные аудитории, поиск слотов
  plan.py       совместная расстановка нескольких занятий («собрать предмет в один день»)
  cli.py        командный интерфейс
```

```bash
python -m suai_rasp dump                # слепок → schedule.json (53 запроса, ~30 c)
python -m suai_rasp validate            # 0 конфликтов = парсер и модель в порядке
python -m suai_rasp show --group 1232
python -m suai_rasp free --day Среда --slot 3 --campus "Б. Морская 67" --groups 2
python -m suai_rasp slots --group 1232 --subject "Обработка навигационной" --kind Лекция
python -m suai_rasp move  --group 1232 --subject "Обработка навигационной" --to "Четверг 3"
```

Проверка одной гипотезы — доли миллисекунды: расписание не копируется, а
пересчитываются конфликты только у затронутых аудиторий, преподавателей и групп.

### 9.1 Язык гипотез (Python)

```python
from suai_rasp.model import Schedule
from suai_rasp import conflicts as C

sch = Schedule.from_json("schedule.json")
lesson = [l for l in sch.by_group[sch.find_group("1232")]
          if "Обработка навигационной" in l.subject and l.kind == "Лекция"][0]

# одиночный перенос
print(C.report(sch, [C.Move(lesson, day="Четверг", slot=3)]))

# обмен двух занятий местами
print(C.report(sch, C.swap(a, b)))

# перенос со сменой аудитории и чётности недели
C.Move(lesson, day="Пятница", slot=2, week=C.WEEK_ODD, room=Ref(45, "13-04 (Б. Морская 67)"))

# все допустимые слоты
for c in C.candidate_slots(sch, lesson, keep_room=True):
    print(c["day"], c["slot"], c["rooms_total"], c["warnings"])
```

`check_hypothesis` возвращает пару списков: **появившиеся** проблемы и
**исчезнувшие**. Второе не менее важно — так видно, что перенос не просто
допустим, а чинит существующее неудобство (например, убирает переезд между
корпусами).

Классификация проблем:

| `severity` | `kind` | Смысл |
|---|---|---|
| `error` | `group` / `teacher` / `room` | двойное бронирование — гипотеза невозможна |
| `error` | `campus` | переезд Б. Морская ↔ другой корпус за перерыв (соседние пары) |
| `warning` | `campus` | переезд Ленсовета ↔ Гастелло (практикуется) |
| `error` | `commute` | 2 и более переезда через весь город (Б. Морская ↔ другой корпус) за день — любые пары, не только соседние; Ленсовета ↔ Гастелло в счёт не идёт |
| `error` | `window` | у **группы** окно ≥ `MIN_IDLE_WINDOW` (2) пар за день, не объяснённое переездом; у преподавателей не проверяется |
| `warning` | `capacity` | групп больше, чем когда-либо ставили в эту аудиторию |
| `warning` | `room` | коллизия в «общей» аудитории (спортзал) |

`commute` и `window` — в отличие от остальных строк таблицы, это не факты о
реальном расписании ГУАП (см. §7, п. 6), а собственные запреты этого
инструмента для оценки новых гипотез; в опубликованных данных нарушений обеих
категорий сотни.

### 9.2 От требования к гипотезе

Как ваши пожелания к расписанию превращаются в проверяемые гипотезы:

| Требование | Гипотеза | Проверка |
|---|---|---|
| «не хочу первую пару» | перенести все занятия со слота 1 | `candidate_slots(..., slots=[2,3,4])` для каждого |
| «убрать окно в среду» | сдвинуть пару после окна на слот раньше | `Move(l, slot=l.slot-1)` |
| «лабораторные только в 13-03а» | переставить занятия в эту аудиторию | `Move(l, room=Ref(34, ...))` + проверка `room_busy` |
| «день без пар» | перенести всё с этого дня | набор `Move` разом — конфликты между ними учитываются |
| «поток должен помещаться» | смена аудитории | `free_rooms(..., min_groups=N)` |
| «не бегать между корпусами» | `validate` по группе | issue `kind="campus"`, severity `error` |
| «поменять местами две пары» | обмен | `C.swap(a, b)` |

Гипотезы можно составлять пакетами — `check_hypothesis` принимает список
`Move` и проверяет их совместно, включая конфликты переносимых занятий между
собой.

## 10. Что API не даёт

* вместимость аудиторий и их оснащение;
* календарные даты занятий (только день недели + чётность; сопоставление с датами
  — через номер текущей недели из шапки);
* расписание сессии и консультаций;
* учебные планы, нагрузку преподавателей, численность групп;
* историю изменений — только текущее состояние на дату сборки;
* прошлые и будущие семестры.
